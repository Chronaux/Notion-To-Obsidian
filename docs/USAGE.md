# Notion → Obsidian · Rust 0.6.7

## Версия 0.6.7 — отключение системной рамки ComboBox

- Выявлено, что светлую внутреннюю рамку продолжает рисовать UxTheme родительского ComboBox с классом `DarkMode_Explorer`; изменение только дочерних EDIT/STATIC и последующая заливка полос не отключали эту отрисовку.
- Для всех ComboBox в главном окне и настройках используется общий `apply_dark_combo`: системная тема отключается через `SetWindowTheme(hwnd, L"", L"")`, дочерние части очищаются от edge styles, затем включается единый GDI-subclass.
- Внешняя рамка, область значения, разделитель и кнопка раскрытия полностью оформляются одной тёмной палитрой. Popup остаётся нативным owner-draw ComboBox с клавиатурной навигацией и выбором мышью.
- Добавлены регрессионные проверки общего helper и отсутствия `DarkMode_Explorer` на родительском ComboBox. Обычные EDIT-поля не изменены; новых зависимостей нет.


Переносимое приложение Windows 10/11 x64. Последнюю успешно проверенную версию скачивайте с [GitHub Releases](https://github.com/Chronaux/Notion-To-Obsidian/releases/latest/download/NotionToObsidian_Windows_x64.zip). В ZIP лежит готовый EXE; Rust, Python и другие среды не нужны. Новый релиз появляется только после успешной сборки и проверки на Windows.

## Версия 0.6.6 — удаление внутренней белой полосы ComboBox

- По пикселям скриншота выявлена дополнительная светлая полоса толщиной около 1 px внутри внешней рамки области выбранного значения.
- После штатного `WM_PAINT` приложение заполняет внутренние верхнюю, нижнюю и левую полосы цветом поля `FIELD`, сохраняя единственный внешний контур и тёмный разделитель перед кнопкой раскрытия.
- У внутренних EDIT/STATIC-частей отключена визуальная тема; снимаются `WS_BORDER`, `WS_EX_CLIENTEDGE` и `WS_EX_STATICEDGE`, чтобы системные дочерние рамки не появлялись повторно.
- Одинаковая отрисовка используется в главном окне и настройках. Добавлены регрессионные проверки геометрии внутренних полос, внешних краёв и разделителя.
- Сохранены owner-draw строки, штатное раскрытие и клавиатурная навигация, DPI-масштабирование и нативный Win32 без новых зависимостей.

## Версия 0.6.5 — исправление рамки ComboBox

- Устранена светлая рамка в области выбранного значения ComboBox. Ранее перерисовывались стрелка и внешняя рамка окна, но отдельная граница display/value-части оставалась под системной отрисовкой Windows.
- После штатной отрисовки owner-drawn значения приложение теперь перерисовывает в клиентской области все стороны поля, включая вертикальный разделитель перед кнопкой раскрытия. Используется единая тёмная рамка и фиолетовый акцент при фокусе.
- Одинаковая отрисовка применяется в главном окне и в настройках через общий Win32 subclass.
- Удалён неэффективный обход через `GetWindowDC` / `WM_NCPAINT`; добавлены регрессионные проверки именно для внутренней границы выбранного значения.
- Сохранены раскрывающийся список, owner-draw строк, DPI-масштабирование и нативный Win32 без новых зависимостей.

## Версия 0.6.4 — тёмная внутренняя часть выпадающих списков

- Исправлена первопричина светлой рамки в ComboBox. У выпадающего списка есть внутренний дочерний контрол отображения выбранного значения (EDIT/STATIC); прежняя версия оформляла только родительский ComboBox, поэтому внутренний контрол сохранял стандартную светлую 3D-рамку.
- При создании ComboBox приложение теперь находит дочерние EDIT/STATIC-контролы, применяет к ним тёмную тему и снимает лишние `WS_BORDER` / `WS_EX_CLIENTEDGE`. Внешняя рамка остаётся единой и рисуется самим ComboBox.
- Цвет фона и текста внутренних частей также берётся из палитры поля, в том числе во всплывающем окне настроек.
- Добавлены регрессионные проверки поиска, оформления и обработки дочерних контролов. Новых зависимостей нет.

## Версия 0.6.3 — исправление белой рамки ComboBox

- Внешняя рамка выпадающих списков теперь перерисовывается в неклиентской области через `GetWindowDC` после `WM_NCPAINT` и `WM_PAINT`. Это перекрывает светлую системную рамку, которую не затрагивала прежняя отрисовка через `GetDC`.
- Рамка использует палитру приложения: нейтральный тёмный контур и акцент при фокусе. Обновление учитывает смену фокуса и состояния доступности.
- Убрана повторная отрисовка внешнего контура в клиентской области; стрелка и разделитель остаются нативными Win32-элементами с нашей тёмной отрисовкой.
- Добавлены регрессионные проверки для неклиентской отрисовки. Новых зависимостей нет.

## Версия 0.6.2 — восстановление текста выпадающих списков и чекбоксов

- Исправлен неверный тип элемента в Win32 `WM_DRAWITEM`/`WM_MEASUREITEM`: для ComboBox используется `ODT_COMBOBOX = 3`, а не `ODT_LISTBOX = 2`. Выбранные значения и строки раскрытых списков снова отображаются.
- Раскрытые списки используют тёмный фон через `WM_CTLCOLORLISTBOX`.
- Для чекбоксов сохранена системная логика `BS_AUTOCHECKBOX`, а подписи отрисовываются как отдельные тёмные `STATIC`-метки с доступным кликом. Это устраняет чёрный текст при включённых визуальных стилях Windows.
- Добавлены регрессионные UI-проверки правильных типов сообщений и чекбоксов. Отдельная ручная проверка графического окна Windows всё ещё необходима.

## Версия 0.6.1 — исправление тёмного интерфейса
- Выпадающие списки профиля и настроек больше не используют белую системную заливку: элементы списка, рамка и стрелка отрисовываются в общей тёмной палитре приложения.
- Кнопки «Загрузить JSON», «Сохранить JSON», «Отмена» и «Применить» используют собственную нативную Win32-отрисовку вместо белых стандартных кнопок.
- Исправлен цвет текста чекбоксов в окне настроек: подписи теперь читаемы на тёмном фоне.
- Сохранены нативные контролы, выбор пунктов, редактирование, клавиатурная навигация и масштабирование от DPI. Новых зависимостей нет.

## Версия 0.6.0 — профили и предпросмотр
- В главном окне добавлен выбор профиля и кнопки «Настроить…» / «Предпросмотр». По умолчанию **«База знаний»**, совместимая с прежним экспортом.
- «Универсальный» оставляет базы в исходном дереве и не создаёт отдельные CSS, плагин и стартовую заметку. В настройках можно выбирать иерархию, родительские страницы, размещение баз, Markdown/Bases, оглавления, callout и теги.
- Профили импортируются и экспортируются локальными JSON-файлами с `schema_version: 1`. Сохранение путей пользовательского ZIP и результата в профиль не предусмотрено. Переопределения отдельных баз доступны через JSON.
- «Предпросмотр» определяет пути и счётчики без создания хранилища. Кнопка «Отменить» доступна при выполнении анализа.
- CLI: `--profile universal|knowledge` или `--config FILE.json`. Обычный CLI без новых флагов ведёт себя как прежняя версия.
- Формат исходного экспорта остаётся **Markdown & CSV**, не HTML. См. [спецификацию](EXPORT_PROFILES.md).

## Что изменилось в 0.4.0

- Исправлены пустые Bases при открытии внешней папки результата: фильтры учитывают дополнительный префикс `Vault/` и другие обёртки. Настройки оформления и вложенный плагин присутствуют как во внешней папке, так и внутри Vault.
- В Properties остаются исходные поля Notion и нативные `tags`. Автоматические `title`, `folder`, `cssclasses`, `notion_*` и `db_<uuid>_*` не создаются. Исходный «Вопрос» не дублируется автоматически созданным title. Полные названия записей показаны в Bases через ссылку с подписью из исходного поля.
- Отключён повтор имени файла над оригинальным H1 страницы: длинные заголовки берутся из текста, а не из сокращённого имени файла.
- Содержание восстанавливается по заголовкам страницы: блок Table of contents отсутствует в Markdown-экспорте Notion. При наличии минимум двух заголовков создаётся локальное оглавление, если его ещё нет. Это реконструкция по документу, а не восстановление скрытых настроек исходного блока.
- Отдельно стоящая ссылка на базу заменяется встроенной полной таблицей на той же странице. Источник таблицы хранится отдельно, а Obsidian показывает его через штатное встраивание блока `![[…#^notion-table]]`. Открывать отдельную страницу для чтения таблицы не нужно. Ссылки в предложениях сохраняются ссылками.
- Убраны отдельные строки с эмодзи-иконками в начале callout. Подходящие значки превращаются в типы `tip`, `warning`, `danger`, `info` и другие; короткий заголовок становится заголовком плашки. Содержимое кода не меняется.
- Копирование ячеек и дополнительный полный вид Bases также учитывают открытие внешней папки.

Для готового EXE v0.4.0 открывайте вложенную папку `Vault`. Начиная с версии 0.5.1 **сама новая папка результата является корнем хранилища**, а отчёты будут скрыты от дерева Obsidian в `.notion-to-obsidian/`. Не преобразовывайте архив поверх старого хранилища: иначе останутся файлы прежней структуры.

## Изменения 0.3

- Структура папок восстанавливается по разделам оглавления корневой страницы Notion. Например, `Материалы/Раздел А/Задачи.md`. Имена разделов берутся из заголовков, одинаковые страницы разных разделов различаются по UUID. Служебные суффиксы папок убираются там, где владелец определён однозначно.
- Названия колонок — из CSV Notion. Удалены имена `db_<uuid>_...` и дублирующая колонка названия. Имена таблиц соответствуют названиям исходных баз.
- Все значения сохраняются целиком в стандартных Properties. Лимит 240 символов и превью удалены. Полный текст также остаётся в заметках.
- `Тег`, `Тэг`, `Теги`, `Тэги`, `Tag`, `Tags` объединяются в встроенное свойство **tags**. Многословная метка остаётся одной: `Раздел А` → `Раздел_А`. Разделителями нескольких тегов считаются запятая, точка с запятой и перевод строки. Чисто числовые метки получают префикс `тег_`.
- На страницах баз по умолчанию создаются обычные Markdown-таблицы с полным текстом, переносами и неограниченной высотой строк. Они читаются без сторонних плагинов. Настройка оформления уже включена в новом хранилище.
- Bases сохранены рядом для фильтрации и редактирования. Встроенная таблица Bases имеет только фиксированные высоты, поэтому используется увеличенная высота строк, но обещания показать любой объём текста в стандартном виде нет.

## Запуск

1. Выберите ZIP экспорта Notion **Markdown & CSV**. Можно перетащить его в окно приложения или на EXE.
2. При необходимости включите «Создавать отчёт о переносе» (по умолчанию выключен).
3. В разделе «Новое хранилище Obsidian» выберите кнопкой «Обзор» **родительскую папку** через Проводник. Программа предложит путь к новой папке хранилища; существующая папка результата не перезаписывается. Затем нажмите **«Конвертировать»**. Для отмены нажмите эту же кнопку во время работы.
4. В Obsidian откройте **саму папку результата** как хранилище (начиная с v0.5.5). Для готовой v0.4.0 откройте подпапку `Vault`.
5. Откройте заметку «Начать здесь» или корневую «Материалы».

**Отчёт о переносе.** Оба отчётных файла создаются только при установленном чекбоксе. При выключенном чекбоксе структурный аудит, проверки вложений и статистика выполняются так же, а `import-state.json` сохраняется для внутреннего состояния. В CLI отчёт по-прежнему создаётся по умолчанию.

**Пропуск отсутствующих страниц.** В GUI флажок «Пропускать отсутствующие страницы» включён по умолчанию; при необходимости его можно снять. Для CLI используйте явный `--skip-missing`. Отсутствующие страницы с Notion ID останутся внешними ссылками; их UUID, адреса и источники перечислены в `skipped_pages` файла `.notion-to-obsidian/migration-report.json`, если отчёт включён. Ссылки без ID сохранят заглушки и попадут в `missing_pages`. ZIP Markdown & CSV не содержит достоверного признака архивирования, поэтому автоматического распознавания архивных страниц нет.

Полные таблицы встроены в статьи. Отдельно можно открыть заметку с именем базы (`.md`), а не только одноимённый файл `.base`. В новом хранилище включён CSS-snippet `notion-full-tables`. Если вы вручную переносите заметки в другой Vault, перенесите и включите этот snippet через «Оформление → Фрагменты CSS».

## Копирование по клику и полный вид Bases

В экспорт уже вложен небольшой плагин **Notion Full Tables**. Скачивать его отдельно не требуется. Он не отправляет данные по сети и записывает в буфер только по нажатию пользователя.

Для включения: **Настройки → Сторонние плагины → разрешить сторонние плагины для этого хранилища → включить Notion Full Tables**. Программа не отключает ограниченный режим Obsidian и не включает плагин автоматически.

После включения:

- В режиме просмотра Markdown-таблицы клик по обычному тексту ячейки копирует её **целиком**, включая переводы строк и адреса. Клик по ссылке открывает ссылку. Если выделен текст, копирование по клику не перехватывается. Доступны Enter/пробел для фокуса на ячейке.
- В меню представлений `.base` доступен **«Полный текст · копировать»**. В нём нет фиксированной высоты строк, а данные читаются из текущих Properties записей.

Обычная Markdown-таблица и её данные копирования — снимок при экспорте. Если затем редактируете записи в Obsidian, используйте дополнительный вид Bases: он обновляется по текущим свойствам. Без плагина полные Markdown-таблицы остаются доступными; текст можно выделить и скопировать Ctrl+C.

## Устройство результата

Начиная с v0.5.5 **папка результата** содержит страницы, вложения, `.base`, полные Markdown-таблицы и `.obsidian`; лишнего каталога `Vault` нет. Служебные `import-state.json` и инструкция находятся в скрытой `.notion-to-obsidian/`, а `migration-report.json` создаётся там только при включённом отчёте. В v0.4.0 действует прежняя структура с `Vault/` и отчётами рядом с ним.

Сохраняются все записи полных CSV `_all.csv`, а также состав и порядок строк текущего вида. Неоднозначные строки сохраняются отдельно с предупреждением. Копируемые блоки кода сохраняются; их содержимое проверяется по хешам после разбора Markdown. Вложения проверяются SHA-256.

## Ограничения

- Только Markdown & CSV ZIP. API и HTML-экспорт не подключены.
- Повторная конвертация создаёт новый снимок; автоматического слияния локальных правок нет.
- Если UUID конкретного блока не сопоставим с текстом экспорта, ссылка ведёт на страницу целиком; это отмечается в отчёте, если он включён.
- Формулы, rollup и условия фильтров не восстанавливаются из отображаемых CSV-значений. Состав текущего вида хранится как снимок строк.
- Область оглавления задаёт папки. Разделы без явного родителя сохраняются в «Другие сервисы»; исходные связи и оглавления остаются доступны.
- Кроме явно распознаваемых тегов, типы свойств CSV не угадываются: значения сохраняются текстом, чтобы не потерять ведущие нули и смысл меток.
- Внешние страницы/картинки автоматически не скачиваются. Вложения из ZIP локализуются. Внешние гиперссылки сохраняются.
- Предел распаковки: 8 ГБ всего / 2 ГБ на файл. Файлы читаются в память.

## Проверка

Проверка конвертера выполняется на синтетических архивах в `tests/converter.rs`; реальные пользовательские экспорты не включены в исходники.

Перед выпуском выполняются Rust-тесты, проверки UI, сборка Windows x64 и smoke-тест. Количество тестов и статус смотрите в журнале актуальной сборки GitHub Actions.

Проверенная сборка предназначена для Windows x64. Перед публикацией следуйте [рекомендациям по конфиденциальности](PRIVACY.md), включая проверку истории и старых релизов.

## Разработчику

- `cargo test --locked`
- `cargo build --release --locked`
- Linux → Windows: цель `x86_64-pc-windows-gnu` и MinGW-w64; `cargo build --release --locked --target x86_64-pc-windows-gnu`. Для manifest/version resource нужен `x86_64-w64-mingw32-windres`.
- Проверка фильтров реального результата: `node tests/bases.cjs RESULT_FOLDER`.
- Проверка плагина: `NODE_PATH=/path/to/node_modules node tests/plugin.cjs`, с установленным `jsdom@26` (только для теста).
- Командная строка: `notion-to-obsidian ARCHIVE.zip OUTPUT_FOLDER [--skip-missing]` или `notion-to-obsidian ARCHIVE.zip --inspect` (доступно в новых сборках, но не в v0.4.0).

Лицензии зависимостей: THIRD_PARTY_NOTICES.txt и папка licenses. Исходный пользовательский экспорт в приложение и исходники не включён.
