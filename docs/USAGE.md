# Notion → Obsidian · Rust 0.5.1

Переносимое приложение Windows 10/11 x64. Последнюю успешно проверенную версию скачивайте с [GitHub Releases](https://github.com/Chronaux/Notion-To-Obsidian/releases/latest/download/NotionToObsidian_Windows_x64.zip). В ZIP лежит готовый EXE; Rust, Python и другие среды не нужны. Новый релиз появляется только после успешной сборки и проверки на Windows.

## Версия 0.5.1

- Убрано **автоматическое создание файла «Оглавление.md» в каждой папке**. Теперь раздел — только папка; оглавление по заголовкам остаётся в тексте самой страницы, если оно уместно. Настоящие страницы Notion с названием «Оглавление» сохраняются.
- Готовая Windows x64 сборка автоматически создаётся GitHub Actions при изменениях в main и доступна через [GitHub Releases](https://github.com/Chronaux/Notion-To-Obsidian/releases/latest) после успешных тестов. Не требуется установка среды разработки.

## Подготовлено в v0.5.0

- Нативный тёмный интерфейс: фон, поля ввода, журнал, кнопки, флажок, строка заголовка Windows (при поддержке ОС).
- Собственная иконка EXE и окна приложения; внешние темы/фреймворки не используются.
- Папка результата — корень хранилища Obsidian, без дополнительного `Vault/`. Служебные отчёты находятся в `.notion-to-obsidian/`.
- Необязательный пропуск вручную проверенных отсутствующих страниц сохраняет внешние ссылки и фиксирует пропущенные UUID в отчёте.
- Состояние текущей сборки и результаты проверок: [GitHub Actions](https://github.com/Chronaux/Notion-To-Obsidian/actions/workflows/windows-release.yml).

## Что изменилось в 0.4.0

- Исправлены пустые Bases при открытии внешней папки результата: фильтры учитывают дополнительный префикс `Vault/` и другие обёртки. Настройки оформления и вложенный плагин присутствуют как во внешней папке, так и внутри Vault.
- В Properties остаются исходные поля Notion и нативные `tags`. Автоматические `title`, `folder`, `cssclasses`, `notion_*` и `db_<uuid>_*` не создаются. Исходный «Вопрос» не дублируется автоматически созданным title. Полные названия записей показаны в Bases через ссылку с подписью из исходного поля.
- Отключён повтор имени файла над оригинальным H1 страницы: длинные заголовки берутся из текста, а не из сокращённого имени файла.
- Содержание восстанавливается по заголовкам страницы: блок Table of contents отсутствует в Markdown-экспорте Notion. При наличии минимум двух заголовков создаётся локальное оглавление, если его ещё нет. Это реконструкция по документу, а не восстановление скрытых настроек исходного блока.
- Отдельно стоящая ссылка на базу заменяется встроенной полной таблицей на той же странице. Источник таблицы хранится отдельно, а Obsidian показывает его через штатное встраивание блока `![[…#^notion-table]]`. Открывать отдельную страницу для чтения таблицы не нужно. Ссылки в предложениях сохраняются ссылками.
- Убраны отдельные строки с эмодзи-иконками в начале callout. Подходящие значки превращаются в типы `tip`, `warning`, `danger`, `info` и другие; короткий заголовок становится заголовком плашки. Содержимое кода не меняется.
- Копирование ячеек и дополнительный полный вид Bases также учитывают открытие внешней папки.

Для готового EXE v0.4.0 открывайте вложенную папку `Vault`. В версии 0.5.1 **сама новая папка результата является корнем хранилища**, а отчёты будут скрыты от дерева Obsidian в `.notion-to-obsidian/`. Не преобразовывайте архив поверх старого хранилища: иначе останутся файлы прежней структуры.

## Изменения 0.3

- Структура папок восстанавливается по разделам оглавления корневой страницы Notion. Например, `Инструкция/Веб Учитель/Домашние задания.md`. Имена разделов берутся из заголовков, одинаковые страницы разных разделов различаются по UUID. Служебные суффиксы папок убираются там, где владелец определён однозначно.
- Названия колонок — из CSV Notion. Удалены имена `db_<uuid>_...` и дублирующая колонка названия. Имена таблиц соответствуют названиям исходных баз.
- Все значения сохраняются целиком в стандартных Properties. Лимит 240 символов и превью удалены. Полный текст также остаётся в заметках.
- `Тег`, `Тэг`, `Теги`, `Тэги`, `Tag`, `Tags` объединяются в встроенное свойство **tags**. Многословная метка остаётся одной: `Веб Учитель` → `Веб_Учитель`. Разделителями нескольких тегов считаются запятая, точка с запятой и перевод строки. Чисто числовые метки получают префикс `тег_`.
- На страницах баз по умолчанию создаются обычные Markdown-таблицы с полным текстом, переносами и неограниченной высотой строк. Они читаются без сторонних плагинов. Настройка оформления уже включена в новом хранилище.
- Bases сохранены рядом для фильтрации и редактирования. Встроенная таблица Bases имеет только фиксированные высоты, поэтому используется увеличенная высота строк, но обещания показать любой объём текста в стандартном виде нет.

## Запуск

1. Выберите ZIP экспорта Notion **Markdown & CSV**. Можно перетащить его в окно приложения или на EXE.
2. «Проверить архив» показывает состав баз и сопоставление записей.
3. Укажите **новую** папку результата и нажмите «Преобразовать».
4. В Obsidian откройте **саму папку результата** как хранилище (начиная с v0.5.1). Для готовой v0.4.0 откройте подпапку `Vault`.
5. Откройте заметку «Начать здесь» или корневую «Инструкция».

**Ручное исключение отсутствующих страниц (с v0.5.1).** Отметьте в окне «Не создавать заглушки отсутствующих страниц Notion (проверено вручную)» только после собственной проверки. Для CLI используйте `--skip-missing`. Все отсутствующие страницы с Notion ID останутся внешними ссылками; их UUID, адреса и источники перечислены в `skipped_pages` файла `.notion-to-obsidian/migration-report.json`. Ссылки без ID сохранят заглушки и попадут в `missing_pages`. ZIP Markdown & CSV не содержит достоверного признака, что страница архивная или удалённая, поэтому автоматического определения нет, а опция по умолчанию отключена.

Полные таблицы встроены в статьи. Отдельно можно открыть заметку с именем базы (`.md`), а не только одноимённый файл `.base`. В новом хранилище включён CSS-snippet `notion-full-tables`. Если вы вручную переносите заметки в другой Vault, перенесите и включите этот snippet через «Оформление → Фрагменты CSS».

## Копирование по клику и полный вид Bases

В экспорт уже вложен небольшой плагин **Notion Full Tables**. Скачивать его отдельно не требуется. Он не отправляет данные по сети и записывает в буфер только по нажатию пользователя.

Для включения: **Настройки → Сторонние плагины → разрешить сторонние плагины для этого хранилища → включить Notion Full Tables**. Программа не отключает ограниченный режим Obsidian и не включает плагин автоматически.

После включения:

- В режиме просмотра Markdown-таблицы клик по обычному тексту ячейки копирует её **целиком**, включая переводы строк и адреса. Клик по ссылке открывает ссылку. Если выделен текст, копирование по клику не перехватывается. Доступны Enter/пробел для фокуса на ячейке.
- В меню представлений `.base` доступен **«Полный текст · копировать»**. В нём нет фиксированной высоты строк, а данные читаются из текущих Properties записей.

Обычная Markdown-таблица и её данные копирования — снимок при экспорте. Если затем редактируете записи в Obsidian, используйте дополнительный вид Bases: он обновляется по текущим свойствам. Без плагина полные Markdown-таблицы остаются доступными; текст можно выделить и скопировать Ctrl+C.

## Устройство результата

Начиная с v0.5.1 **папка результата** содержит страницы, вложения, `.base`, полные Markdown-таблицы и `.obsidian`; лишнего каталога `Vault` нет. Служебные `migration-report.json`, `import-state.json` и инструкция перенесены в скрытую `.notion-to-obsidian/`. В v0.4.0 действует прежняя структура с `Vault/` и отчётами рядом с ним.

Сохраняются все записи полных CSV `_all.csv`, а также состав и порядок строк текущего вида. Неоднозначные строки сохраняются отдельно с предупреждением. Копируемые блоки кода сохраняются; их содержимое проверяется по хешам после разбора Markdown. Вложения проверяются SHA-256.

## Ограничения

- Только Markdown & CSV ZIP. API и HTML-экспорт не подключены.
- Повторная конвертация создаёт новый снимок; автоматического слияния локальных правок нет.
- Если UUID конкретного блока не сопоставим с текстом экспорта, ссылка ведёт на страницу целиком; это отмечено в отчёте.
- Формулы, rollup и условия фильтров не восстанавливаются из отображаемых CSV-значений. Состав текущего вида хранится как снимок строк.
- Область оглавления задаёт папки. Разделы без явного родителя сохраняются в «Другие сервисы»; исходные связи и оглавления остаются доступны.
- Кроме явно распознаваемых тегов, типы свойств CSV не угадываются: значения сохраняются текстом, чтобы не потерять ведущие нули и смысл меток.
- Внешние страницы/картинки автоматически не скачиваются. Вложения из ZIP локализуются. Внешние гиперссылки сохраняются.
- Предел распаковки: 8 ГБ всего / 2 ГБ на файл. Файлы читаются в память.

## Проверка

На предоставленном архиве: 535 исходных страниц, 388 записей сопоставлены с Markdown, 32 базы, 274 вложения. Восстановлены 13 разделов. В 243 заметках есть нативный `tags` (288 значений). 11 отсутствующих целей представлены заглушками. 280 копируемых блоков сохранены. Независимый разбор: 593 Markdown-файла результата и 57 таблиц.

23 теста Rust прошли. Все 32 базы проверены при трёх вариантах корневого пути: без префикса, Vault/ и Копия/Vault/; состав всех записей и текущего вида совпадает с экспортом. Восстановлены 88 оглавлений и 31 встроенная таблица. Отдельно проверены обработчики плагина в DOM: полный текст, клавиатура, сохранение поведения ссылок, очистка обработчиков и дополнительный вид Bases. Эта проверка использует имитацию API, а не установленный Obsidian.

Последняя успешная сборка из GitHub Releases рассчитана на Windows x64 без дополнительных установок. **Запуск окна этой сборки на настоящей Windows и визуальная проверка в самом Obsidian в среде сборки не выполнены.** Предыдущую версию пользователь подтвердил как работающую; логика окна в 0.4 не менялась, кроме номера версии.

## Разработчику

- `cargo test --locked`
- `cargo build --release --locked`
- Linux → Windows: цель `x86_64-pc-windows-gnu` и MinGW-w64; `cargo build --release --locked --target x86_64-pc-windows-gnu`. Для manifest/version resource нужен `x86_64-w64-mingw32-windres`.
- Проверка фильтров реального результата: `node tests/bases.cjs RESULT_FOLDER`.
- Проверка плагина: `NODE_PATH=/path/to/node_modules node tests/plugin.cjs`, с установленным `jsdom@26` (только для теста).
- Командная строка: `notion-to-obsidian ARCHIVE.zip OUTPUT_FOLDER [--skip-missing]` или `notion-to-obsidian ARCHIVE.zip --inspect` (доступно в новых сборках, но не в v0.4.0).

Лицензии зависимостей: THIRD_PARTY_NOTICES.txt и папка licenses. Исходный пользовательский экспорт в приложение и исходники не включён.
