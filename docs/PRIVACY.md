# Конфиденциальность и безопасная публикация

Конвертер работает локально с ZIP-экспортом Notion Markdown & CSV. Он не требует учётной записи Notion, токенов API или подключения к сети. Программа сохраняет ссылки и исходные ID страниц в локальном результате, если они нужны для восстановления связей. Это **пользовательские данные**, которые не следует публиковать вместе с исходным кодом.

## Что не следует коммитить

- Реальные ZIP-экспорты Notion, CSV/HTML, изображения, документы, экспортированные Obsidian vault и папки `.obsidian` / `.notion-to-obsidian`.
- `migration-report.json`, `import-state.json`, журналы ошибок, результаты конвертации и реальные имена файлов, которые могут раскрыть содержимое базы.
- `.env`, токены, ключи, пароли, файлы сертификатов, абсолютные пути домашнего каталога, настоящие ссылки на приватные страницы и таблицы.
- Скриншоты интерфейса с реальными именами, контактами, URL, внутренними документами или содержимым рабочих систем.

Тесты должны использовать **только синтетические документы**, вымышленные имена и фиктивные UUID. Список исключений в `.gitignore` — дополнительная защита, но он не предотвращает добавление файлов через `git add -f` и не защищает от секретов внутри обычных исходников/Markdown.

## Перед переключением приватного репозитория на public

1. Запустите `python scripts/privacy_scan.py` из корня Git-репозитория и отдельную проверку секретов, например `gitleaks git .`, на полном локальном клоне.
2. Просмотрите **все** коммиты, отдельные ветки, теги, PR, issues, релизы, вложения и логи Actions — опубликованные бинарные архивы могут содержать старые версии документации.
3. Если приватные данные когда-либо были закоммичены, очистите историю с `git-filter-repo` в отдельном резервном клоне, удалите старые ссылки и теги, а также перевыпустите или удалите прежние release-артефакты. Обычный `git rm` не очищает историю.
4. Отзовите и замените любые токены, пароли и ключи, когда-либо попавшие в коммиты, даже если файл удалён.
5. Убедитесь, что в GitHub Actions и настройках репозитория нет сведений, которые вы не хотите раскрывать. Учтите, что имя владельца и авторы коммитов в публичном репозитории видны.
6. **Не переводите репозиторий в public до завершения очистки всех ссылок и артефактов.** Самый безопасный путь, если невозможно очистить старую историю и Releases, — создать новый публичный репозиторий из проверенного чистого снимка, а исходный оставить приватным.
