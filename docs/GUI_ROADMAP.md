# План развития интерфейса Notion → Obsidian

Цель: понятное и доступное нативное приложение Windows 10/11 без WebView, Electron, дополнительной установки и отправки пользовательских данных по сети. Преобразование ZIP и защита от перезаписи существующего Vault остаются без изменения, пока отдельная задача не предусматривает обратного.

## P1 — надёжность и удобство выбора

- [ ] Валидировать ZIP и расположение результата непосредственно после изменения пути: отсутствие архива, недоступная директория, запрет записи, одинаковые/вложенные пути. Не запускать опасную операцию.
- [ ] Использовать Known Folders API для каталога документов Windows (включая перенаправление в OneDrive), а не формировать путь из `USERPROFILE/Documents`.
- [ ] Добавить явное описание итогового пути до запуска и различать «папку-родителя» и «создаваемое хранилище».
- [ ] Сохранять последний выбранный каталог **только по согласию** и без путей/содержимого пользовательских экспортов в логи или Git.
- [ ] Добавить отдельную проверку создания/неперезаписи папки при конкурирующих запусках.

**Критерии:** при некорректных путях пользователь получает конкретную ошибку до начала работы; не создаются лишние каталоги; старое хранилище не меняется.

## P2 — доступность и визуальная адаптация

- [ ] Проверить и устранить обрезание длинных путей, статуса и кнопок; дать подсказки полного пути при наведении.
- [ ] Проверить Win32-отрисовку на Windows 10/11, 100/150/200% DPI, маленьких мониторах и при системном увеличенном шрифте.
- [ ] Обеспечить последовательную Tab-навигацию, Enter/Esc, видимый фокус, читабельные имена кнопок для экранных дикторов.
- [ ] Единые состояния disabled, hover, pressed и error для всех элементов; проверить контраст и отсутствие мерцания.
- [ ] Добавить интерактивные Windows UI smoke-тесты только в существующий процесс проверок, если это окажется устойчивым; **не добавлять новый GitHub Actions workflow без отдельного запроса**.

**Критерии:** все действия доступны мышью и клавиатурой, текст различим, а основные элементы не перекрываются при изменении DPI.

## P3 — управление импортом

- [ ] После конвертации показывать краткую сводку страниц, баз, файлов и предупреждений в окне, без раскрытия частного содержимого.
- [ ] Для включённого отчёта предусмотреть «Открыть отчёт» после конвертации; при ошибке показывать краткую причину и путь к локальному отчёту, если он сформирован.
- [ ] Добавить просмотр отличий между двумя экспортами в режиме **без записи** и отдельно исследовать безопасный инкрементальный импорт, не затрагивающий пользовательские изменения в Obsidian.
- [ ] Измерить потребление памяти на больших ZIP и отзывчивость кнопки отмены; избегать полного обновления окна на каждый тик.

**Критерии:** пользователь видит объём переноса и последствия операции до записи; отчёты остаются только локальными; никакие существующие заметки не перезаписываются без явного подтверждения и отдельной реализации.

Полный перечень опций, умолчаний, ограничений и схема интерфейса — [docs/EXPORT_PROFILES.md](EXPORT_PROFILES.md). Не считать эти пункты функциональностью v0.5.14.

## Проверка каждого изменения

1. `cargo test --locked`, `node tests/ui.cjs`, `cargo build --release --locked --target x86_64-pc-windows-gnu`.
2. Синтетический ZIP: выбор, конвертация с отчётом и без него, отмена, повторная попытка и готовый Vault без вложенной папки.
3. Ручная проверка интерактивных диалогов Windows; текущие CI smoke-тесты проверяют EXE через CLI и не гарантируют корректный выбор папки мышью.
4. Отсутствие новых зависимостей времени выполнения, токенов, личных путей, частных экспортов и автоматизации через новые workflows.

Приоритеты можно перенести в GitHub Issues по мере начала конкретных задач, без изменения уже опубликованных релизов.
