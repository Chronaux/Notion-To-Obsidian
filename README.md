# Notion → Obsidian

Переносимое приложение на **Rust** для преобразования ZIP-экспорта Notion в готовое хранилище Obsidian: страницы, вложения, внутренние ссылки, Properties, теги и базы данных.

**Windows 10/11 · x64 · v0.6.2 · нативный Win32 · полностью локально**

## Профили экспорта (v0.6.0)

Начиная с v0.6.0 в главном окне можно выбрать **«Универсальный»**, **«База знаний»** или **«Пользовательский»**. Профиль **«База знаний» выбран по умолчанию для совместимости** с предыдущими версиями; он сохраняет старое размещение баз в `Базы данных/`, оглавления, встроенные таблицы и дополнения Obsidian.

- **Универсальный:** физическая иерархия Notion, базы рядом с исходными страницами, без искусственной группировки, стартовой заметки, CSS и плагина.
- **База знаний:** прежний результат v0.5.14, включая размещение родительских страниц и таблиц.
- **Пользовательский:** откройте «Настроить…», измените правила и нажмите «Применить». Через этот же диалог можно загрузить/сохранить JSON с настройками. Профиль JSON содержит **только параметры**, а не ZIP, пути хранилища или заметки. Правила для отдельных баз по UUID и колонки тегов задаются в JSON.

Кнопка **«Предпросмотр»** рассчитывает структуру будущего хранилища и выводит первые 32 пути без записи файлов. Для больших ZIP анализ может потребовать чтения всего архива; во время анализа работает «Отменить». Полный конвертер по-прежнему создаёт **только новую** папку Vault.

CLI также принимает `--profile universal|knowledge` и `--config profile.json`. Без указания профиля CLI сохраняет прежнее поведение. Пример:

```powershell
NotionToObsidian_v0.6.2.exe export.zip D:\Obsidian\MyVault --profile universal
NotionToObsidian_v0.6.2.exe export.zip D:\Obsidian\MyVault --config profile.json
```

Точная схема JSON, режимы вывода `markdown_only` / `bases_only` и ограничения описаны в [спецификации профилей](docs/EXPORT_PROFILES.md). Для всех режимов ZIP должен быть экспортирован из Notion как **Markdown & CSV**; HTML-экспорт пока не поддерживается. В v0.6.2 редактирование индивидуальных настроек каждой базы через GUI ещё не предусмотрено — используется JSON.

## Что переносится

| В Notion | В Obsidian |
| --- | --- |
| Страницы и подстраницы | Markdown и папки; если страница содержит подстраницы, её Markdown хранится **внутри** папки этих подстраниц; разделы корневого оглавления восстанавливают иерархию |
| Ссылки на экспортированные страницы | Внутренние wikilinks |
| Ссылки на внешние сайты | Сохраняются |
| Ссылки Notion на конкретные блоки | Если точная позиция не сохранена в экспорте, переходят на локальную страницу; исходная ссылка и ID блока сохраняются в `block_link_fallbacks` при включённом отчёте |
| Изображения и файлы в ZIP | Локальные вложения с проверкой SHA-256 |
| Поля записей и теги | Нативные Properties и `tags`, без автоматически добавленных ID, `title` и `folder` |
| Базы CSV | Markdown, `.base` и записи; расположение и формат выбираются профилем (в профиле «База знаний» — папка `Базы данных/`) |
| Ссылка на базу отдельным блоком | Таблица, встроенная прямо в родительскую статью |
| Table of contents | Оглавление, реконструированное по заголовкам страницы |
| Callout и toggle | Нативные callout Obsidian; отдельная строка с эмодзи-иконкой убирается |
| Блоки кода | Сохраняются с проверкой содержимого |

Статьи с базами данных **остаются в разделах инструкций**. На таких страницах таблицы видны напрямую — как в Notion — благодаря встроенным ссылкам Obsidian. Сами таблицы, файлы Bases и заметки записей вынесены в отдельный корневой каталог, повторяющий исходную иерархию.

Пример структуры результата:

```text
Материалы/
  Раздел А/
    Проект.md        # статья со встроенной таблицей
Базы данных/
  Материалы/
    Раздел А/
      Проект/
        Проект.md     # полная таблица
        Проект.base   # фильтры и виды Bases
        Запись.md                   # отдельная запись базы
```

В Obsidian можно свернуть папку `Базы данных`, чтобы она не отвлекала при чтении инструкций.

**Обычные вложенные страницы** (не записи CSV-базы) размещаются вместе со своим родителем:

```text
Материалы/
  Раздел А/
    Проект/
      Проект.md  # содержимое родительской статьи
      Подстраница А.md
      Подстраница Б.md
```

Так не возникает пары `Проект.md` и `Проект/` рядом друг с другом. В Obsidian папка и Markdown-страница остаются разными сущностями: для открытия статьи нужно выбрать вложенную заметку. Если каталог содержит записи CSV-базы, статья продолжает находиться в дереве инструкций, а записи — в `Базы данных/`.

## Как пользоваться

1. В Notion экспортируйте страницу с настройками **Markdown & CSV**, **Everything**, **Include subpages** и **Create folders for subpages**. Для текущего вида базы подходит **Current view**.
2. Запустите приложение и выберите ZIP. Архив также можно перетащить в окно или на EXE. Значок **«?»** рядом с заголовком ZIP показывает настройки экспорта при наведении; по нажатию открывает то же пояснение.
3. При необходимости установите флажок **«Создавать отчёт о переносе»**. Он выключен по умолчанию; при включении конвертер создаст в новом хранилище Markdown-отчёт и диагностический JSON.
4. В строке **«Новое хранилище Obsidian»** нажмите **«Обзор»**: откроется системный Проводник для выбора родительского каталога. Приложение подставит новый путь `Notion_Obsidian` (если он занят — `Notion_Obsidian_2` и далее). Можно также вручную ввести полный путь несуществующей папки. Нажмите **«Конвертировать»**. Во время работы кнопка становится **«Отменить»**.
5. Откройте в Obsidian **саму папку результата** — заметки и `.obsidian` уже в её корне. Только старая сборка v0.4.0 использует вложенную папку `Vault`.

Для повторной конвертации выбирайте отдельную новую папку: программа создаёт новый снимок и не объединяет его с локальными правками старого хранилища. В строке ZIP кнопка «Обзор» открывает выбор файла; архив можно также перетащить в окно.

[План дальнейшего развития интерфейса](docs/GUI_ROADMAP.md) — приоритеты, критерии готовности и проверки Windows. [Проект профилей и настроек экспорта](docs/EXPORT_PROFILES.md) — будущие универсальный профиль, профиль совместимости и настройки отдельных баз (пока не реализованы).

## Таблицы без обрезания ответов

Основной вид — Markdown-таблицы с полным текстом ячеек и переносами строк. Они встроены в статьи и работают без сторонних плагинов. CSS для оформления уже включён в новом хранилище.

Рядом сохраняется `.base` для фильтрации и редактирования. Есть представления **«Экспортированный вид»** и **«Все записи»**. Стандартный вид Bases сохраняет ограничения самого Obsidian по высоте строк.

Для копирования ячейки целиком по клику включите вложенный плагин **Notion Full Tables**: **Настройки → Сторонние плагины → разрешить плагины → Notion Full Tables**. Он также добавляет в Bases представление **«Полный текст · копировать»** без фиксированной высоты строк. Плагин не включается автоматически и не отправляет данные по сети.

Markdown-таблица — снимок на момент конвертации. Дополнительный вид Bases показывает текущие Properties и подходит для дальнейшего редактирования записей.

## Результат

- **Корень папки результата** — папки `Материалы/`, `Базы данных/`, `_attachments/`, заметки начала работы и настройки `.obsidian` (если такие материалы присутствуют в экспорте).
- **`Отчёт о переносе.md` и `.notion-to-obsidian/migration-report.json`** — создаются только при включённом чекбоксе в GUI. Содержат сводку, предупреждения и сопоставления ссылок; по умолчанию в GUI оба отсутствуют.
- **.notion-to-obsidian/import-state.json** — соответствия страниц и контрольные суммы.
- Пока конвертация не начата, компактное окно не содержит нижних пояснений. После запуска появляется область статуса с полосой прогресса; по завершении показываются реальные счётчики и кнопка открытия результата. Подробности сохраняются в отчёте, если он включён.
- **`block_link_fallbacks` в отчёте** (если он включён) — переходы, для которых Markdown & CSV не позволяет восстановить точную позицию блока. Страница и её содержимое переносятся в обоих режимах; исходный URL сохраняется в JSON только при включённом отчёте.

В графическом интерфейсе флажок **«Пропускать отсутствующие страницы» включён по умолчанию**, его можно снять перед обработкой. Для отсутствующих страниц с распознанным Notion ID заглушки не создаются, ссылки остаются внешними, а адреса и источники фиксируются в `skipped_pages`, если отчёт включён. Если ID отсутствует, заглушка сохраняется. Markdown & CSV экспорт не позволяет достоверно определить, что страница архивная; пропуск применяется именно к **отсутствующим** страницам. В CLI опция по-прежнему включается явно через `--skip-missing`. В CLI и библиотечном API генерация отчётов остаётся включённой по умолчанию для совместимости. Диагностический CLI-режим `--inspect` сохранён.

**Важно:** версии начиная с 0.5.1 не создают отдельные `Оглавление.md` для папок. Оглавление по заголовкам страницы остаётся **внутри самой страницы**, а реальные документы Notion с названием «Оглавление» сохраняются. Внешние страницы и изображения автоматически не скачиваются.

## Ограничения

- Поддерживается ZIP **Markdown & CSV**. HTML-экспорт и Notion API пока не используются.
- Формулы, rollup и логика фильтров Notion не восстанавливаются из CSV. Значения и состав текущего вида сохраняются как снимок.
- Если Markdown-экспорт не содержит ID блока, ссылку невозможно точно направить к его позиции. Она открывает локальную страницу целиком, а исходный URL доступен в `block_link_fallbacks`. Это ограничение ссылок, не потеря содержимого и не предупреждение об ошибке.
- Типы полей, кроме тегов, не угадываются: CSV-значения сохраняются текстом.
- Предел распаковки: 8 ГБ суммарно и 2 ГБ на файл; содержимое обрабатывается в памяти.

## Разработка и проверка

Исходники ядра — `src/lib.rs`, нативного окна Windows — `src/gui.rs`. Плагин Obsidian находится в `assets/notion-table-copy`.

```sh
cargo test --locked
cargo build --release --locked
node tests/ui.cjs  # статическая проверка иконки и темы
```

Сборка Windows автоматизирована через [GitHub Actions](.github/workflows/windows-release.yml): тестирование Rust, кросс-компиляция Windows x64, запуск EXE на Windows, упаковка и публикация ZIP/контрольных сумм в Releases. Также можно запустить workflow вручную. Публикация происходит **только после успешных проверок**. При изменении кода после выпуска увеличивайте версию в Cargo.toml и соответствующих файлах ресурсов.

Проверки запускаются через `cargo test --locked` и тесты интерфейса. Для публикации используются только синтетические данные; результаты проверки частного экспорта не размещаются в репозитории.

Фактический статус сборки v0.6.2 смотрите в [GitHub Actions](https://github.com/Chronaux/Notion-To-Obsidian/actions/workflows/windows-release.yml). Предыдущие результаты v0.4.0 не заменяют проверку v0.6.2; бинарный архив публикуется только после автоматических тестов.

## Конфиденциальность исходных данных

Конвертация выполняется локально: ZIP-экспорт и созданное хранилище не отправляются на сервер. Не добавляйте в GitHub свои ZIP-экспорты, отчёты, готовые Obsidian-хранилища, токены или скриншоты с личными данными. Подробности и чек-лист перед публикацией: [docs/PRIVACY.md](docs/PRIVACY.md).
