# Notion → Obsidian

Переносимое приложение на **Rust** для преобразования ZIP-экспорта Notion в готовое хранилище Obsidian: страницы, вложения, внутренние ссылки, Properties, теги и базы данных.

**Windows 10/11 · x64 · v0.5.6 · нативный Win32 · полностью локально**

## Что переносится

| В Notion | В Obsidian |
| --- | --- |
| Страницы и подстраницы | Markdown и папки; разделы корневого оглавления используются для восстановления иерархии |
| Ссылки на экспортированные страницы | Внутренние wikilinks |
| Ссылки на внешние сайты | Сохраняются |
| Ссылки Notion на конкретные блоки | Если точная позиция не сохранена в экспорте, переходят на локальную страницу; исходная ссылка и ID блока сохраняются в `block_link_fallbacks` отчёта |
| Изображения и файлы в ZIP | Локальные вложения с проверкой SHA-256 |
| Поля записей и теги | Нативные Properties и `tags`, без автоматически добавленных ID, `title` и `folder` |
| Базы CSV | Таблицы Markdown, файлы `.base` и записи — в отдельной папке `Базы данных/` на верхнем уровне хранилища |
| Ссылка на базу отдельным блоком | Таблица, встроенная прямо в родительскую статью |
| Table of contents | Оглавление, реконструированное по заголовкам страницы |
| Callout и toggle | Нативные callout Obsidian; отдельная строка с эмодзи-иконкой убирается |
| Блоки кода | Сохраняются с проверкой содержимого |

Статьи с базами данных **остаются в разделах инструкций**. На таких страницах таблицы видны напрямую — как в Notion — благодаря встроенным ссылкам Obsidian. Сами таблицы, файлы Bases и заметки записей вынесены в отдельный корневой каталог, повторяющий исходную иерархию.

Пример структуры результата:

```text
Инструкция/
  Веб Учитель/
    Поурочное планирование.md        # статья со встроенной таблицей
Базы данных/
  Инструкция/
    Веб Учитель/
      Поурочное планирование/
        Поурочное планирование.md     # полная таблица
        Поурочное планирование.base   # фильтры и виды Bases
        Занятие.md                   # отдельная запись базы
```

В Obsidian можно свернуть папку `Базы данных`, чтобы она не отвлекала при чтении инструкций.

## Как пользоваться

1. В Notion экспортируйте страницу с настройками **Markdown & CSV**, **Everything**, **Include subpages** и **Create folders for subpages**. Для текущего вида базы подходит **Current view**.
2. Запустите приложение и выберите ZIP. Архив также можно перетащить в окно или на EXE.
3. При необходимости нажмите **«Проверить ZIP»**, чтобы посмотреть состав и сопоставление записей.
4. Выберите новую папку результата и нажмите **«Конвертировать»**. Пока идёт работа, эта же кнопка становится **«Отменить»**.
5. Откройте в Obsidian **саму папку результата** — заметки и `.obsidian` уже в её корне. Только старая сборка v0.4.0 использует вложенную папку `Vault`.

Для повторной конвертации выбирайте отдельную новую папку: программа создаёт новый снимок и не объединяет его с локальными правками старого хранилища.

## Таблицы без обрезания ответов

Основной вид — Markdown-таблицы с полным текстом ячеек и переносами строк. Они встроены в статьи и работают без сторонних плагинов. CSS для оформления уже включён в новом хранилище.

Рядом сохраняется `.base` для фильтрации и редактирования. Есть представления **«Экспортированный вид»** и **«Все записи»**. Стандартный вид Bases сохраняет ограничения самого Obsidian по высоте строк.

Для копирования ячейки целиком по клику включите вложенный плагин **Notion Full Tables**: **Настройки → Сторонние плагины → разрешить плагины → Notion Full Tables**. Он также добавляет в Bases представление **«Полный текст · копировать»** без фиксированной высоты строк. Плагин не включается автоматически и не отправляет данные по сети.

Markdown-таблица — снимок на момент конвертации. Дополнительный вид Bases показывает текущие Properties и подходит для дальнейшего редактирования записей.

## Результат

- **Корень папки результата** — папки `Инструкция/`, `Базы данных/`, `_attachments/`, заметки начала работы и настройки `.obsidian` (если такие материалы присутствуют в экспорте).
- **.notion-to-obsidian/migration-report.json** — проверки, предупреждения, пропущенные и недостающие страницы.
- **.notion-to-obsidian/import-state.json** — соответствия страниц и контрольные суммы.
- Нижняя часть окна показывает текущий этап конвертации и плавную полосу прогресса вместо журнала. Количество обработанных страниц/баз/файлов берётся из реальных счётчиков; подробности и предупреждения остаются в отчёте.
- **`block_link_fallbacks` в отчёте** — не ошибки конвертации, а переходы, для которых Markdown & CSV не позволяет восстановить точную позицию блока. Страница и её содержимое переносятся; исходный URL сохраняется для точного перехода через Notion. Служебная папка с точкой не загромождает список заметок.

В графическом интерфейсе флажок **«Пропускать отсутствующие страницы» включён по умолчанию**, его можно снять перед обработкой. Для отсутствующих страниц с распознанным Notion ID заглушки не создаются, ссылки остаются внешними, а адреса и источники фиксируются в `skipped_pages` отчёта. Если ID отсутствует, заглушка сохраняется. Markdown & CSV экспорт не позволяет достоверно определить, что страница архивная; пропуск применяется именно к **отсутствующим** страницам. В CLI опция по-прежнему включается явно через `--skip-missing`.

**Важно:** версии начиная с 0.5.1 не создают отдельные `Оглавление.md` для папок. Оглавление по заголовкам страницы остаётся **внутри самой страницы**, а реальные документы Notion с названием «Оглавление» сохраняются. Внешние страницы и изображения автоматически не скачиваются.

## Ограничения

- Поддерживается ZIP **Markdown & CSV**. HTML-экспорт и Notion API пока не используются.
- Формулы, rollup и логика фильтров Notion не восстанавливаются из CSV. Значения и состав текущего вида сохраняются как снимок.
- Если Markdown-экспорт не содержит ID блока, ссылку невозможно точно направить к его позиции. Она открывает локальную страницу целиком, а исходный URL доступен в `block_link_fallbacks`. Это ограничение ссылок, не потеря содержимого и не предупреждение об ошибке.
- Типы полей, кроме тегов, не угадываются: CSV-значения сохраняются текстом.
- Предел распаковки: 8 ГБ суммарно и 2 ГБ на файл; содержимое обрабатывается в памяти.

## Разработка и проверка

Исходники ядра — `src/lib.rs`, нативного окна Windows — `src/gui.rs`. Плагин Obsidian находится в `assets/notion-table-copy`.

```sh
cargo test --locked
cargo build --release --locked
node tests/ui.cjs  # статическая проверка иконки и темы
```

Сборка Windows автоматизирована через [GitHub Actions](.github/workflows/windows-release.yml): тестирование Rust, кросс-компиляция Windows x64, запуск EXE на Windows, упаковка и публикация ZIP/контрольных сумм в Releases. Также можно запустить workflow вручную. Публикация происходит **только после успешных проверок**. При изменении кода после выпуска увеличивайте версию в Cargo.toml и соответствующих файлах ресурсов.

В v0.4.0 прошли 23 Rust-теста и DOM-проверки плагина. На контрольном экспорте проверены 535 страниц, 388 записей CSV, 32 базы, 274 вложения и 280 блоков кода. Фильтры всех баз проверены при трёх вариантах корневого пути. [Отчёт о проверке](VALIDATION_v0.4.0.json).

Фактический статус сборки v0.5.6 смотрите в [GitHub Actions](https://github.com/Chronaux/Notion-To-Obsidian/actions/workflows/windows-release.yml). Предыдущие результаты v0.4.0 не заменяют проверку v0.5.6; бинарный архив публикуется только после автоматических тестов.
